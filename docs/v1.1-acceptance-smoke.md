# v1.1 cleanup-phase acceptance smoke test

5-minute operator-run checklist that closes out the cleanup phase
(PCleanup.9.5).  Run on a real project file with at least 2 layers and a
mask defined.  Capture observations inline; check off each line as you
go.

This is the **phase-close gate** for v1.1 — if any acceptance bullet
fails, do NOT bundle a fix into the release PR.  Open a new
PCleanup-aligned task and ship the fix in its own commit.

## Pre-flight

- [ ] `make ci` is clean on the branch you're about to tag (the
  release-candidate build).  This document was written against the
  branch that ships with **1126/1126 tests passing** post-`v3`-default.
- [ ] You're on macOS — v1 is macOS-only.
- [ ] A `*.rmap.json` project loads cleanly (no audit-blocking findings).
- [ ] At least one Image / Video / SVG layer exists in the project with a
  mask polygon (mask edge ≥ 4 vertices) so SDF-consuming Treatments
  have something to bind.

## 1. SourceModifier Treatments — visible source manipulation (3 min)

Apply ≥4 distinct SourceModifier Treatments across ≥2 layers and
confirm each one **manipulates the underlying photo** (not just an
overlay).

The 12 source-modifying Treatments shipped in v1.1 (Cleanup Phase) are
listed under the **"Source-modifying"** group separator in the Treatment
picker (PCleanup.2.12).  Pick any four — recommended starter set:

- [ ] **`fluid_warp`** — increase `amplitude`; the photo warps along
  velocity field lines, bounded by the mask.  At `amplitude = 0` the
  output is bit-identical to the source.
- [ ] **`ripple_lens`** — increase `amplitude`; concentric refraction
  rings appear at the mask edge and refract the photo.
- [ ] **`zone_brighten`** — requires `ZONE_WINDOW` zone tag on the
  warp.  Increase `intensity`; the photo brightens inside the zone with
  exponential edge falloff.  Outside the zone or with no zone tag, no
  effect.
- [ ] **`spotlights`** — particles drift inside the mask; pull
  `brightness_gain` up to see soft luminance lifts under each particle.
  Particle count controls the number of bright spots.

In each case, verify:
- Default state (sliders at min / identity) → operator can see the
  Treatment is loaded but **no visual change vs. source**.
- Pulling the primary slider up → operator can see the source pixels
  being warped / lifted / masked, **not** an opaque overlay drawn on
  top of the source.

## 2. `Effect::Feedback` — visible trails (30 sec)

Stack an `Effect::Feedback { decay, offset }` on one layer.

- [ ] At `decay = 0.0` → no trail (instant fade).
- [ ] At `decay = 0.95` → long ghosting trail.
- [ ] At `decay = 1.0` → infinite hold (paint stays forever; mute the
  layer briefly to reset).
- [ ] If the `audio` feature is compiled in: change `decay` to a
  `Modulator::Audio` binding; trails respond to band 0 (bass) bouncing.

## 3. OSC parameter binding (30 sec)

Bind any FX-preset slider to a `Modulator::OscBound` address.  From a
second machine, send an OSC packet to the bound address at port 7777.

- [ ] The bound slider moves when OSC arrives within one frame.
- [ ] The existing OSC commands (TapTempo, SceneRecall, CueGo,
  Blackout, Freeze) still work — no regression.

If you don't have an OSC sender handy, this section can be skipped;
the `live_registry_round_trip` automated test (in
`src/modulators/osc.rs`) covers the wiring at unit-test level.

## 4. Cue-strip thumbnails (10 sec)

Open the cue strip in the control window.

- [ ] Three or more cue thumbnails show **real scene contents**, not
  name-hash gradients (PCleanup.7.1).
- [ ] Modifying a scene → its thumbnail updates on next scene-save.
- [ ] Resizing the control window → thumbnails re-register cleanly.

## 5. BPM modulator divisor selector (10 sec)

Add a `Modulator::Bpm` to any slider (PCleanup.bpm-divisor):

- [ ] The "rate" dropdown shows four options: `1/2 (double-time)`,
  `1 (every beat)`, `2 (half-time)`, `4 (quarter-time)`.
- [ ] Selecting each option changes the modulator's period without
  needing to type a raw `divisor` value.

## 6. Per-output gamma / brightness / contrast (10 sec)

With ≥1 OutputTarget configured (PCleanup.7.3):

- [ ] Per-output gamma slider visibly changes that output's gamma.
- [ ] Two outputs can hold independent values.

## 7. No regressions (15 sec)

- [ ] Existing generative-overlay presets (`mask_edge_ripple_wash`,
  `mask_edge_wave_wash`, `particles_identity`, `fx_zone_light_spill`,
  `fx_zone_edge_ripple`, `fx_zone_portal_drift`) still render
  identically to v1.0.x.
- [ ] No `warn!` log spam from Treatment / Effect dispatch — every
  registered preset has an active dispatch arm.

## Automated coverage (informational)

The following parts of this smoke are also exercised by the test
harness (`make ci`):

- All 12 SourceModifier Treatment registry entries + descriptor
  ranges + identity-default rules.
- `Effect::Feedback` mix-and-blit math (CPU-side numerical check).
- `Modulator::OscBound` value-registry round-trip.
- BPM-divisor preset snap-to-nearest semantics.
- `MoveBezierAnchor` undo round-trip is bit-exact (proptest).

The operator path covers the **integration** layer (project loads,
GPU renders, sliders wired through) that CI can't reach without
running the binary against real hardware.
