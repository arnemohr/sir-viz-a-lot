# 004 v3.1 — patch release scope

**Position:** patch release between **v3.0 ship** and **v0.4** (Phase 0
in `004-phase-0.md`). All items here are "deferred from v3 because they
would have added schema churn or test surface without operator-visible
benefit at v0.3.0" — they are cleanup plus small-but-valuable adds that
do not gate v3.0 and do not need engine work as large as v0.4.

**Naming:** v3.1 is a patch release, not a roadmap phase. Listed in the
spec-004 series for index continuity with `specs/roadmap.md` §4.2; uses
`004-v3.1.md` rather than `004-phase-X.md` to make the distinction
visible in the file listing.

Sources for this scope: `specs/roadmap.md` §4.2 (deferred audit findings,
schema v6 portable monitor, Reverse-storage refactor, native macOS menu
bar, demo content) plus the four v3.1 candidates added during the
roadmap consolidation.

> **Schema version note.** The roadmap and earlier drafts of this spec
> referred to "schema v5 portable monitor". `CURRENT_SCHEMA_VERSION` was
> bumped to 5 during 003-T3.29 (per-layer warp default), so portable
> monitor is actually a **v5 → v6** migration. This spec uses v6
> throughout; `roadmap.md` §4.2 still says v5 and should be updated to
> match.

---

## Goal

Close the v3-shaped loose ends and ship the small operator UX wins that
fell out of the consolidated UX review but don't justify a Phase 1+
investment. Do this without touching the engine surface area — anything
requiring new subsystems, threading, or external dependencies belongs in
v0.4 (Phase 0).

## Capability set

### Deferred audit findings (all from Spec 003 phase 1)

- **T1.36** — static-value modulator round-trip edge case.
- **T1.37** — `crossfade_duration_s` Reverse-storage under undo.
- **T1.39** — `output_windowed` undo boundary case.
- **T1.40** — empty-effects-vec snapshot parity.

These are silent-corruption traps surfaced during the v3 proptest work;
fixing them is type-system / Reverse-storage discipline, not new
capabilities.

### Schema v6 portable monitor (T4.12, T4.13)

- `output_monitor_index: usize` field becomes
  `OutputTarget { uuid: Option<String>, fallback_index: usize }`.
- On load, prefer UUID match; fall back to index; fall back to
  display 0 + audit warning.
- Enables project portability across machines with different
  monitor orders.
- **Phase 7 extends** this with a full calibration-file split
  (venue-scoped warp + mask + gamma + monitor identity travels
  separately from the show file). v3.1 ships only the schema +
  loader changes.

### Compile-time Reverse-storage refactor (T1.14 follow-on)

- Move from per-variant Reverse-storage convention to a type-level
  guarantee.
- Reduces the risk of silent corruption when adding new `Mutation`
  variants.
- Pure refactor — no runtime behaviour change.

### Native macOS menu bar (T4.19, if not shipped in M4)

- `File / Edit / Window / Help` via `objc2-app-kit::NSMenu`.
- Exposes `Cmd-S`, `Cmd-Shift-S`, `Cmd-O`, `Cmd-Q` as keyboard
  chords (resolves the gap list in `specs/roadmap.md` Appendix A.5).
- About box: version, license, contributors.
- Help → rmap Help: opens README in the default browser (already
  wired in v3 via the `?` button; menu bar adds the chord).
- Linux/Windows: no-op (egui menu suffices).

### Additional demo content

- Film strip demo scene.
- Test grid demo scene.

These exercise the demo-bundle path landed in v3 (the launcher's
"Try a demo" entry).

### Operator UX consolidation candidates

These four items came out of the 2026-05-10 UX review (consolidated
into `specs/roadmap.md` §4.2 "v3.1 candidates added by this
consolidation") and are small enough to ship without Phase-1
engine work:

- **Layer solo / mute on the left rail** (UI item I9 / Recommendation
  H). Visibility toggle exists today; solo / mute is a left-rail
  affordance plus a render-graph hint. Past ~5 layers, missing solo
  is painful. Full media-row anatomy (scrubbing + in/out + loop) for
  video lands in **Phase 1**.
- **BPM HUD + tap badge in the top chrome** (UI item N3 /
  Recommendation I). Live BPM, tap source (Space / MIDI 60 / OSC
  `/rmap/tap`), 1/2/4/8-bar quantize selector for cue firing.
  `Modulator::Bpm` already exists; this is UX-only. Full transport
  HUD with LTC / MTC / MIDI-clock sync lands in **Phase 6**.
- **Persistent output preview thumbnail** in the control window
  header (UI item I7 / Recommendation K). Surfaces the projector
  output at all times, not only inside the preview-as-projector
  window. Phase 7 turns this into the full Output panel.
- **Audio bands strip** (8-band FFT meter + drag-to-bind) when an
  audio source is active (UI item I3 / Recommendation I). The
  audio FFT modulator is already wired in `src/modulators/audio.rs`;
  the missing piece is the operator-facing meter and drag-to-bind.
  Full binding picker UX lands in **v0.4 (Phase 0)**.

## Engine implications

- **Mutation Reverse-storage refactor** is type-system work — no
  runtime behaviour change but eliminates a class of silent-
  corruption bugs as new `Mutation` variants are added.
- **Schema v6 OutputTarget** migration is automatic on load (extends
  the v2 → v3 → v4 → v5 path landed in v3.0).
- **T4.19 menu bar wiring** is macOS-only via `objc2-app-kit`; the
  Linux / Windows fallback is the existing egui menu (already
  sufficient for chord-less use).
- **No new threading / SDK / decoder dependencies** — that's the
  bright line between v3.1 and v0.4.

## Capability lens

- **Operator usability + cross-cutting reliability.** v3.1 is not
  a lens-driven release; it's the small cleanups that make v3.0
  feel finished before v0.4 starts adding capability.

## Out of scope for v3.1

- **Video / NDI input / second projector / OSC binding UI / MIDI
  parameter binding / per-projector RGB calibration / FxLayer
  foundations** → all **v0.4 (Phase 0)**.
- **Effect chain reordering or preset library** → **Phase 2**.
- **Cuelist with per-cue timing fields** → **Phase 6**.
- **Art-Net / sACN output, fixture groups, color-from-pixel** →
  **Phase 5**.
- **Calibration file split (venue-scoped calibration decoupled
  from content)** → **Phase 7**. v3.1 ships only the schema-side
  groundwork (UUID-based monitor identity).
- **Bezier mesh warp, inverse mask, luma / chroma key** → **Phase 7**.

## Usability rule

Every v3.1 add must be **introducible in a one-line CHANGELOG entry**
that an existing v3.0 operator can immediately understand. If a v3.1
item needs a paragraph of context, it belongs in v0.4 or later.

## Acceptance criteria

- The Mutation proptest harness in `src/project/` covers all four
  deferred findings (T1.36, T1.37, T1.39, T1.40) and they pass.
- A project saved on machine A loads on machine B with the same
  monitor matched by UUID; falls back gracefully when the UUID is
  not present (uses index, then display 0 with an audit warning).
- `Cmd-S` / `Cmd-Shift-S` / `Cmd-O` / `Cmd-Q` work on macOS through
  the native menu and behave identically to their toolbar / OS
  equivalents.
- Layer solo / mute survives undo / redo / scene recall (proptest
  coverage extended).
- BPM HUD shows live BPM and tap source label; quantize selector
  affects cue-firing timing.
- Output preview thumbnail renders the same content as the
  projector with no measurable extra GPU cost (verify with
  `make test-gpu` golden-image harness).
- Audio bands meter is visible when an audio source is active;
  each band is a drag-source for parameter binding (full picker
  ships in v0.4 — v3.1 only needs the meter + drag-source
  affordance).
- The bundled demo project library has at least four entries
  (current "discoball_complete" + film strip + test grid + the
  existing window-glow demo).
- Compile-time Reverse-storage refactor lands without changing
  observable behaviour (existing tests pass; new test confirms a
  new `Mutation` variant cannot compile without proper
  Reverse-storage).
